## 1. 기능 요구사항

| ID | 기능명 | 요구사항 | 사용자/행위자 | 우선순위 | 검증 기준 | 근거 |
|---|---|---|---|---|---|---|
| FR_01 | 분실물 조회 | 시스템은 학생이 등록된 분실물의 보관 여부를 조회할 수 있도록 해야 한다. | 분실 학생 | 필수 | 등록된 보관 중 물품을 조회했을 때 해당 물품의 보관 여부가 표시된다. 검색 조건은 TBD_01 확정 후 보완한다. | NEEDS_1, SC1, S1 |
| FR_02 | 보관 위치 표시 | 시스템은 조회된 분실물의 보관 위치를 학생에게 표시해야 한다. | 분실 학생 | 필수 | 조회 결과에서 해당 물품의 보관 위치를 확인할 수 있다. 공개할 위치 정보의 상세 수준은 TBD_04 확정 후 보완한다. | NEEDS_1, SC1, S1 |
| FR_03 | 분실물 등록 | 시스템은 행정 담당자가 조회에 필요한 분실물 정보를 등록할 수 있도록 해야 한다. | 행정 담당자 | 필수 | 행정 담당자가 필수 정보를 입력하면 물품이 저장되고 조회 대상에 반영된다. 필수 입력 항목은 TBD_02 확정 후 보완한다. | NEEDS_2, SC2, S2 |
| FR_04 | 인도 상태 관리 | 시스템은 행정 담당자가 물품의 상태를 `보관 중` 또는 `인도 완료`로 기록하고 변경할 수 있도록 해야 한다. | 행정 담당자 | 필수 | 각 물품에는 두 상태 중 하나가 표시되며, 상태 변경 후 조회 결과에 변경 상태가 반영된다. 처리 권한과 정정 절차는 TBD_03 확정 후 보완한다. | NEEDS_3, SC3, S2 |
| FR_05 | 상태별 물품 구분 | 시스템은 보관 중인 물품과 인도 완료된 물품을 구분하여 조회할 수 있도록 해야 한다. | 분실 학생, 행정 담당자 | 필수 | 동일한 조회 화면 또는 조회 조건에서 두 상태가 명확히 구별된다. | NEEDS_3, SC3, S2 |
| FR_06 | 문의 정보 안내 | 시스템은 분실 학생에게 보관 담당 부서와 해당 부서에 문의할 방법을 표시해야 한다. | 분실 학생 | 필수 | 조회 화면에서 담당 부서와 승인된 문의 방법을 확인할 수 있으며 개인 휴대전화 번호는 표시되지 않는다. 구체적인 표시 항목은 TBD_05 확정 후 보완한다. | NEEDS_4, SC6, S4, S5 |

## 2. 비기능 요구사항

### 2.1 품질 요구사항

| ID | 품질 특성 | 요구사항 | 목표/검증 기준 | 상태 | 근거 |
|---|---|---|---|---|---|
| NFR_01 | 사용성 | 학생은 행정실을 방문하기 전에 분실물의 보관 여부, 보관 위치 및 문의 방법을 이해할 수 있어야 한다. | 대표 사용자 시나리오에서 사용자가 조회 결과만으로 보관 여부·위치·문의 방법을 식별할 수 있는지 확인한다. 구체적인 성공률과 소요 시간은 TBD_06에서 정한다. | 부분 정의 | 서비스 목표, NEEDS_1, NEEDS_4 |
| NFR_02 | 업무 효율성 | 분실물 등록 절차는 행정 담당자의 등록 부담을 줄일 수 있도록 구성해야 한다. | 현행 등록 소요 시간과 부담 요인을 측정한 뒤 목표 입력 시간 또는 입력 단계 수를 정해 검증한다. 기준값과 목표치는 TBD_07이다. | 목표치 미정 | 서비스 목표, NEEDS_7, S2 |
| NFR_03 | 정보보호 | 조회 화면에는 조회 목적과 운영상 필요성이 승인된 정보만 공개해야 하며, 개인 휴대전화 번호를 노출해서는 안 된다. | 공개 항목 검토 결과와 화면 표시 항목을 대조하고, 개인 휴대전화 번호가 모든 조회 화면에서 노출되지 않는지 확인한다. | 정의 | NEEDS_6, SC8, S4 |
| NFR_04 | 데이터 정확성 | 물품의 현재 상태는 `보관 중`과 `인도 완료` 중 하나로 일관되게 표시되어야 한다. | 동일 물품의 상세 화면과 조회 결과에서 상태 값이 서로 일치하며 동시에 두 상태로 표시되지 않는다. | 정의 | NEEDS_3, SC3 |

### 2.2 기타 비기능 제약

| ID | 구분 | 요구사항 | 검증 기준 | 근거 |
|---|---|---|---|---|
| NFR_05 | 데이터 제약 | 개발 및 검증에는 가상 데이터만 사용해야 한다. | 테스트 데이터와 배포 자료를 점검해 실제 개인정보가 포함되지 않았음을 확인한다. | C_1 |
| NFR_06 | 연동 제약 | 이번 개발 범위에서는 학교 인증 시스템과 연동하지 않는다. | 시스템 구성과 외부 연동 목록에 학교 인증 연동이 없음을 확인한다. | C_1 |

> 성능, 가용성, 복구, 호환성 및 구체적인 보안 통제 수준은 기준 문서에 명시되지 않아 본 버전에서 요구사항으로 임의 정의하지 않는다.

## 3. 정책

| ID | 정책명 | 정책 내용 | 적용 대상 | 근거 |
|---|---|---|---|---|
| Pol_01 | 가상 데이터 사용 | 개발, 시연 및 검증에는 가상 데이터만 사용한다. | 전체 시스템 및 데이터 | C_1 |
| Pol_02 | 실제 개인정보 제외 | 실제 개인정보는 시스템의 입력·저장·조회 대상으로 사용하지 않는다. | 데이터 관리 | C_1 |
| Pol_03 | 학교 인증 연동 제외 | v0.1 개발 범위에서는 학교 인증 연동을 구현하지 않는다. | 인증 및 외부 연동 | C_1 |
| Pol_04 | 개인 연락처 비공개 | 개인 휴대전화 번호는 조회 화면을 포함한 사용자 화면에 공개하지 않는다. | 정보 공개 | NEEDS_6, SC8, S4 |
| Pol_05 | 공식 문의 수단 사용 | 사용자에게는 보관 담당 부서와 승인된 문의 방법을 안내하며, 개인 휴대전화 번호를 문의 수단으로 사용하지 않는다. | 문의 안내 | NEEDS_4, NEEDS_6, SC6, SC8 |
| Pol_06 | 사진 조회 기능 제외 | 사진 업로드 및 유사 분실물 비교 기능은 v0.1 범위에서 제외하고 후속 개선 후보로 관리한다. | 개발 범위 | SC5 |
| Pol_07 | 자동 알림 기능 제외 | 사진 매칭 결과를 분실 학생에게 자동 알림하는 기능은 v0.1 범위에서 제외한다. | 개발 범위 | SC7 |
